# 设置导入与备份

本功能已进入源码开发版本；已发布的 `0.2.0-preview.2` 安装包不包含本轮新增界面。没有重新发布二进制前，不改下载清单。

## 使用流程

在“设置与备份”导出 JSON，或选择已有文件进入预览。当前格式为 `app=AppRoute`、`kind=approute-settings`、`version=1`；兼容旧 `application-routing-snapshot` 导出。文件最大 2 MB，最多 5000 条资料，每次选择最多 100 个应用。

预览按本机可读取的程序完整路径匹配；不按名称猜测。已有专属分流默认不勾选，未匹配或共享系统进程不可选择。勾选已有条目意味着明确替换该条目的资料及所选联网方式。

- **仅导入资料**：合并名称、分类和收藏，不应用联网方式。
- **导入并应用**：确认后将所选应用交给原有分流事务；未选应用的规则保持原样。代理应用默认跟随当前绑定组。
- **恢复文件中的代理策略**：默认关闭；打开后还会统一迁移当前代理应用的跟随组。不会更改用户原有代理组的成员或手选节点。
- **恢复显示语言**：默认关闭，独立选择；导入期间的新语言选择不会被旧预览覆盖。

文件保存本机程序路径及代理组/节点名称，请妥善保管，不作为公开诊断附件。它不含订阅、凭据、完整内核配置、自定义图标、辅助进程缓存和连接验证记录。旧的仅进程名规则无法安全迁移到另一台电脑；未匹配项目先扫描或添加正确路径，再重新预览。

## 保留与失败处理

每次导入先保存 `backups/settings` 下的白名单设置快照；不能安全备份时停止导入。设置导入不会直接覆盖 `state.json`、Clash 配置或其他覆写文件。

分流应用复用 `RoutingService.applyAutomatically` 的校验、冲突检查、守护与失败回退；辅助路径由后台重新识别。预览十分钟有效，设置发生变化则需重新预览。资料写入带修订校验，导入后重新加载，防止旧页面缓存覆盖新设置。

网络和多个本地文件不是一个数据库事务。网络应用失败时不保存导入资料；网络成功但后续资料/语言保存失败时，界面明确报告未完成部分并保留导入前备份，不声称整体成功或擅自撤销期间的新选择。

## 实现入口与验证

| 位置 | 职责 |
| --- | --- |
| `src/core/settingsTransfer.ts` | 输入格式、大小、路径与策略校验 |
| `src/shared/settings.ts` | 导出、预览、导入和备份协议 |
| `src/main/services/settingsTransfer.ts` | 本机匹配、预览指纹、合并及安全事务 |
| `src/main/services/settingsBackups.ts` | 备份的限定路径、白名单读取及变更核对 |
| `src/renderer/components/SettingsPage.tsx` | 文件操作、差异预览、勾选与确认 |
| `scripts/verify-settings-ui.mjs` | 隔离 Electron、原生文件入口、四语窄窗口及 IPC 验收 |

`npm run check` 包含格式、旧格式兼容、冲突、旧缓存、原规则保留和失败回退回归；`npm run check:settings-ui` 使用真实桌面与设置存储、模拟路由后台，不接触用户配置。该检查纳入日常 UI CI 与发布前验收，不能代替 Mac 真机分流验证。
