# 代理策略

应用管理顶部的“代理策略”负责统一设置已选择走代理的应用。打开、勾选和排序均为草稿，点击“应用策略”才开始校验、写入与网络检查；取消不改变网络。直接联网和按原规则的应用保持原设置。

| 模式 | 配置与行为 |
| --- | --- |
| 沿用现有策略 | 绑定 Clash Party 已有 Selector、URLTest 或 Fallback 组，不修改组成员或策略。 |
| 故障备用 | 勾选 2 至 32 个远端节点，拖动或使用上下按钮排列优先顺序；Mihomo fallback 使用排在前面的可用节点。优先节点恢复后可能切回，不承诺永久停留在备用节点。 |
| 延迟优先 | 勾选 2 至 32 个候选，Mihomo url-test 按探测延迟与切换容差选节点；延迟不代表下载速度。 |

自动策略使用独立组 `AppRoute · 自动代理`，只作为 AppRoute 代理应用的目标，不把它插入或替换用户原有组。首次默认间隔 60 秒、超时 5 秒、延迟容差 100 ms；高级设置提供有限选项。测试地址为 `https://www.gstatic.com/generate_204`，要求 HTTP 204，非懒惰探测。所有候选探测失败不会自动转 DIRECT；无法保证某个间隔内一定恢复，也不代表所有业务网站可用。旧连接不主动关闭。

当前候选范围为活动配置 `proxies` 明确声明且内核确认的远端节点，不包括组、DIRECT、REJECT 或动态代理集合节点；代理集合可选择“沿用现有策略”。订阅移除部分候选时保留剩余节点的顺序，全部消失时生成只含 REJECT 的有效专用组并提示重选。订阅新节点不自动加入候选，避免扩大用户选择范围。

## 实现与恢复

- `src/shared/proxyStrategy.ts`：跨边界策略类型、名称及初始参数。
- `src/core/proxyStrategy.ts`：输入验证、独立组所有权校验与编译。自包含编译函数同时嵌入 Clash Party 覆写，避免两套生成规则漂移；所有权快照与组对象不能共享引用。
- `RoutingService.setProxyStrategy`：统一迁移代理应用，复用校验、备份、独立守护、重载、出口探测、确认和失败回退。默认组与策略一同回退；直连记录不修改。
- 策略随 AppRoute 自有覆写保存。订阅重新生成时再执行，运行内核继续执行自动选择，不依赖 AppRoute 窗口常驻。本机正常 Clash Party 重启及两份真实订阅往返切换已观察到规则保留；远程订阅成功刷新仍待验证，范围见 [成熟度验收](MATURITY-PLAN.md)。
- 切回已有组时删除专用组；“恢复网络”停用自有规则和专用组。不会删除用户原有组、覆写、订阅或修改系统代理/TUN。原有配置若引用专用组、同名配置被占用或所有权内容被外部修改，拒绝猜测覆盖并提示冲突。
- 状态分别提供策略加载、当前节点、近期探测与应用实际连接。页面连接断开时不继续展示缓存节点为当前事实。创建策略失败不会伪装成成功。

官方字段依据：[代理组](https://wiki.metacubex.one/config/proxy-groups/)、[故障转移](https://wiki.metacubex.one/config/proxy-groups/fallback/)、[自动选择](https://wiki.metacubex.one/config/proxy-groups/url-test/)。
