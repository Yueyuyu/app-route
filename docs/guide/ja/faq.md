# よくある質問

## ルール準備済みなのに未検証なのはなぜ？

読み込みと通信観測は別です。新規接続を作り、詳細を確認します。キャッシュ、既存接続、Clash 外の通信では新しい検証になりません。[初回設定](quickstart.md)をご覧ください。

## 設定済み・実行中・全アプリの違いは？

設定済みは専用分流のあるアプリ、実行中は検出した実行プロセス、全アプリはスキャン一覧です。お気に入りは独立した絞り込みであり、分流設定を意味しません。検索は全アプリが対象ですが、カテゴリや接続方法の絞り込みにも注意してください。

## 新しくインストールしたアプリは？

定期的に変更を確認します。急ぐ場合は再スキャンし、未検出なら手動追加します。ポータブル版、ストアアプリ、共有補助プロセスの全検出は保証しません。

## 接続表示が緑なのにアクセスできないのは？

制御 API につながることを示しています。ノードやサイトの正常性ではありません。ノード、実際の経路、直近の診断時刻を確認してください。

## Clash Party を終了したら？

AppRoute は停止したコアの代わりになりません。システムプロキシが停止したポートを指すと通信が失敗する場合があります。Clash Party を通常起動し、そのシステムプロキシ状態を確認します。AppRoute の復旧対象は自身のルールだけです。

## ショートカットでプロパティが開くのは？

通常は分流と別の問題です。Windows は Alt + ダブルクリックでプロパティを開きます。左右の Alt を押して離し、再試行してください。再発する場合は原因を断定せず、再現手順を報告してください。

## インストールがブロックされたり、ウィンドウが出ない場合は？

Windows は未署名、Mac は未公証です。[配布元とハッシュ](install.md)を確認し、正確な警告を記録してください。具体的な検出を誤検知と決めつけたり、保護を無効にしたりしないでください。警告がなければ起動中のプロセスを確認し、[版と症状を報告](https://github.com/Yueyuyu/app-route/issues/new/choose)します。

## 他クライアント、自動更新、ポータブル版は？

現在の対象は Clash Party です。他クライアントは未検証、自動更新と検証済み Windows ポータブル版はありません。Mac ZIP は単なるアプリの圧縮形式です。

## 元に戻すには？

1 アプリは Clash ルールへ戻し、全体は[ネットワーク復旧](maintenance.md#recovery)を使います。元のユーザールールは保持されます。
