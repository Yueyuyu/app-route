# 常见问题

## 为什么规则就绪了，还没显示已验证？

规则加载和连接观测是两步。让应用建立新连接，再看详情；已缓存内容、旧长连接或未进入 Clash 的流量都不能作为新验证。见[首次使用](quickstart.md)。

## “已设置”“正在运行”“全部应用”怎样区分？

已设置显示有专属分流的应用；正在运行显示检测到运行进程的应用；全部应用显示扫描清单。收藏是独立筛选，不等于已经配置分流。搜索覆盖全部应用，搜索后仍需注意分类和联网方式筛选。

## 新安装的软件怎样出现？

AppRoute 会定期检查应用变化。着急使用时点击“扫描应用”；未识别的软件可以手动添加。便携应用、商店应用和共享辅助进程不保证全部识别。

## 左下角绿色，为什么还是连不上？

绿色表示能连接 Clash 控制接口，不代表所有节点或目标网站可用。查看当前节点、实际连接与自检时间。先确认 Clash Party 自身能联网，再核对应用设置。

## Clash Party 退出后怎么办？

AppRoute 不能代替已停止的代理内核。如果系统代理仍指向停止的端口，网络可能异常。正常重开 Clash Party 并检查它的系统代理状态；AppRoute 的恢复仅处理自身规则，不会擅自关闭其他代理软件。

## 点击快捷方式弹出“属性”，是网络问题吗？

这通常不是网络分流的表现；Windows 的 Alt + 双击会打开属性。可分别按下并松开两侧 Alt 后重试。若仍出现，记录复现步骤；不能仅凭这一现象认定 AppRoute 或某个键盘工具是原因。

## 安装器被拦截或窗口一直不出现？

当前 Windows 包未签名，Mac 未公证。核对[来源与 SHA-256](install.md)，记录系统或安全软件的准确提示。明确的威胁检测需要单独调查；不要直接按“误报”处理，也不要关闭防护。没有提示时，在任务管理器确认是否仍在启动，再[反馈版本和现象](https://github.com/Yueyuyu/app-route/issues/new/choose)。

## 支持其他代理软件、自动更新或便携版吗？

当前正式接入目标是 Clash Party；其他客户端没有经过完整验证。没有自动更新，也没有已验证的 Windows 便携发布包。Mac ZIP 只是应用压缩分发形式。

## 怎样恢复原有设置？

单个应用切回“按 Clash 规则”；全部 AppRoute 分流使用[恢复网络](maintenance.md#恢复网络)。用户原有规则会保留。
