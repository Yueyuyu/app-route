# 首屏加载与交互

本轮目标是让应用列表更早可用，同时减少首屏加载的代码，不改变代理配置或分流判断。

## 行为

- 有本机资料时先显示缓存列表。新应用扫描继续在后台运行，只在没有列表数据时显示表格加载遮罩；扫描按钮和检查时间仍体现扫描状态。
- 设置与备份、图标管理、分流规则/帮助、应用编辑、应用详情、连接详情按首次使用加载。已打开的编辑/详情组件保留关闭动画与键盘行为。
- 图标登记安排在首帧之后；组件卸载或新扫描取代旧资料时，停止继续登记旧批次，减少重复后台工作。
- 初始化语言期间显示轻量启动占位。可选页面加载失败显示局部错误和重试，不隐藏主导航及网络恢复入口。

## 测量范围

同功能构建（已含设置导入与备份）的首屏 JavaScript，从 **1,337,512 字节**降到 **1,275,276 字节**，减少约 **4.7%**。统计入口及全部静态依赖的总和，不仅比较入口文件大小；按 Node 默认 gzip 分文件求和约从 421.8 kB 降到 411.6 kB。桌面从本地读取文件，gzip 只作为辅助指标，不代表实际网络流量或启动耗时。

Ant Design 与 React 的首屏共同依赖仍较大，构建中的大块提示保留，不靠调高告警阈值掩盖。该变化也不意味着每台电脑启动时间会按相同比例下降。

`scripts/check-startup-budget.mjs` 在每次构建统计 Vite manifest 的完整静态依赖，要求上述六个功能模块保持按需加载，首屏 JS 上限为 1,300,000 字节。报告输出至忽略的 `output/startup/bundle.json`。新增功能触碰预算时应先检查依赖是否被误放回首屏，而非直接放宽上限。

## 桌面验证

`npm run check:startup` 使用独立 Electron 配置和虚构应用：人为挂起扫描，确认缓存列表可搜索且没有遮罩；通过 CDP 观察本地资源请求，确认其他页面在使用前未加载。随后仅移除临时夹具中的设置页面文件，验证局部报错、主页面和恢复入口仍可用，补回文件后可重试，并检查帮助模块按需加载。

自定义 `approute://` 协议的资源不一定进入 Resource Timing，因此不用空的资源列表证明“没有加载”。脚本中的耗时是隔离环境受控重新导航的观察值，不是安装版冷启动基准。它不操作真实网络，也不替代完整四语桌面检查和发布前打包验收。
