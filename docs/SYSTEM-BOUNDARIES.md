# 系统影响范围与排查记录

AppRoute 管理应用的联网规则，不接管 Windows 桌面、输入或程序启动。这里只描述当前实现和已验证范围，不宣称用户级后台已经获得操作系统强制隔离，也不保证第三方运行时永远没有缺陷。

## 允许的副作用

| 流程 | 允许范围 | 不应产生的副作用 |
| --- | --- | --- |
| 应用与辅助进程扫描 | 读取开始菜单、安装登记、进程路径、应用清单及图标；缓存写入 AppRoute 数据目录 | 启动被扫描程序、保存其他应用快捷方式、改文件关联、模拟键鼠 |
| 联网设置 | 校验后写 AppRoute 自有覆写与管理记录，通过 Mihomo 重载完整保留原规则的候选配置 | 改系统代理、网卡、TUN、开机启动，结束其他程序或批量关闭连接 |
| 事务恢复 | 恢复本次事务拥有的脚本和管理状态；内核离线时保留待确认结果 | 重置 Windows 网络或假报恢复完成 |
| 桌面窗口 | 显示/隐藏自身窗口，当前窗口菜单快捷键，有限 IPC | 注册全局键盘钩子、注入输入、抢占其他应用的快捷键 |
| 安装与离线入口 | 用户级 AppRoute 安装目录、自身卸载登记、自身桌面/开始菜单/恢复快捷方式 | 提权、注册通用文件关联、改其他软件安装目录或快捷方式 |
| 诊断导出 | 用户在保存对话框选择的文件；内容使用白名单脱敏 | 导出原配置、订阅、访问目标、个人应用清单或凭据 |

PowerShell 只执行固定命令/脚本，后台窗口隐藏并有超时及并发合并。扫描中的 `WScript.Shell.CreateShortcut` 用于读取现有链接，不调用 `Save`；图标使用资源提取 API，不运行 EXE。`process.kill(pid, 0)` 仅探测锁所属进程是否存在，不发送终止信号。

## 共享系统进程保护

资源管理器、系统服务、DLL 宿主、命令解释器等共享进程可能承载多个系统功能，不能把它们当成一个普通应用分流。`core/managedRouting.ts` 的 `assertNoSystemHostRouting` 在自动应用和底层写入入口均执行，检查进程名、主路径与解析后的辅助路径。

这项限制针对新写入。旧版已保存的系统工具记录仍可读取，避免一个历史条目导致整个管理记录失效；选择“按 Clash 规则”可单独撤销，不静默改写已有设置。此保护缩小系统流量影响范围，**不是**“双击弹出属性”的根因修复证据。

## 2026-11-11 排查结果

- 用户报告关闭 Clash Party 后双击多个快捷方式弹出属性；开始排查时用户确认已恢复正常。未复现当时故障。
- 代码审查覆盖扫描、进程识别、桌面主进程/preload/后台、安装、独立恢复和存储入口；未发现模拟键鼠、全局快捷键、系统文件关联修改或其他应用快捷方式保存逻辑。
- 真实扫描得到 196 个应用，读取 239 个运行进程并完成一个本机应用的辅助进程识别。前后 263 个桌面/开始菜单快捷方式内容相同；10 处文件关联、系统代理和辅助键设置相同；5 个受保护的 AppRoute/Clash 配置文件相同。两次 Alt/Ctrl/Shift 状态抽样均未按下。摘要留在本机忽略目录，未公开个人路径或清单。
- 验证辅助脚本最初受父进程 PowerShell 7 模块路径影响，不能加载 Windows PowerShell 的 `Get-FileHash`；只清除该验证子进程继承的模块路径后完成核验。没有改机器环境变量或系统 PowerShell 配置，不能将该验证工具问题当成已确认的产品故障。
- 新增模拟测试：Clash 离线后反复状态读取、自检和新选择不改磁盘；重新连接不自动重放已确认设置；两个写入入口拒绝共享宿主；旧宿主记录保持可读并可单独撤销。完整检查通过 92 项测试及生产构建。
- 开发期间桌面测试工具曾发送窗口快捷键，属于开发工具的输入行为，不在 AppRoute 产品包内。没有故障时刻的按键/焦点证据，无法确认或排除测试工具、键盘状态或其他桌面软件的间接影响。

## 后续复现要求

再次发生时先记录：AppRoute/Clash 是否运行、是否只是关闭窗口或完整退出、双击后打开的是属性还是文件夹，以及 Alt 键释放后是否恢复。先收集故障状态，再做单变量复现；不得为证明无关而先重置注册表、清空快捷方式或改变系统代理。影响范围回归检查和代理退出测试分别记录，网络探测成功不代表桌面输入正常。
