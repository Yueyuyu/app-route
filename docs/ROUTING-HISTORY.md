# 分流操作记录与撤销

桌面应用的「分流规则 → 操作记录」展示最近 20 条分流事务。每条包含时间、来源、结果及应用前后差异；只有展开后才显示进程数量和出口。记录保存在本机，不上传配置或脚本。

来源区分手动设置、设置导入、代理策略、辅助进程补充和撤销。旧版本没有保存的时间及差异显示为缺失，不根据脚本推测。进入写入事务前就拒绝的操作不在此列表；这不是全部系统操作的审计日志。损坏记录保留原文件并提示，不能因为读取失败清空它。

## 单步撤销

仅对具有完整成功快照、仍与当前 revision 和分流内容一致的最近手动/导入操作开放。先显示反向差异，再由用户确认。以下情况保持只读：已有后续修改、当前有未完成事务、代理策略一起变化、旧记录缺少精确路径、主程序路径改变、原记录包含共享系统宿主、自动补充、已撤销或超过一次 100 个应用。

撤销只恢复此次改变的联网方式和原出口，不恢复名称、分类、收藏、语言或整个 Clash 配置。辅助进程由正常分流事务重新识别，不能承诺回到历史进程数量。原程序不存在时停止；取消新增规则不要求已经卸载的程序仍在磁盘上。

## 实现与恢复边界

- `RoutingService` 在既有事务保存来源、候选摘要和确认后的状态。确认记录写入后发生中断时，重新连接核对内核及状态后恢复同一 revision。
- `RoutingHistoryService` 只返回白名单摘要，不返回完整配置、脚本或程序路径。撤销请求只接受事务编号和当前 revision，不能由页面提供历史配置。
- `routingUndoPlan` 统一计算可撤销范围。真正执行仍进入 `applyAutomatically`，再次核对并发修改、所有权及原规则，准备备份和独立恢复，再重载及检查网络；失败自动恢复。
- 预览版安装器没有随源码提交自动升级；历史记录能力需使用包含本次改动的构建。

## 验证

单元回归覆盖过期页面、后续新选择、同 revision 内容漂移、路径失效、共享宿主、失败恢复、确认写入中断、损坏记录和重建服务；反向验证移除并发保护时测试必须失败。四语 Electron 验证展开、取消、Esc 只关闭确认框、冲突提示与窄窗。

`npm run check:recovery-faults` 使用独立 Mihomo、复制的测试进程及回环服务器：撤销前实际连接命中进程路径规则，撤销后同一测试程序的新连接命中原有 MATCH 规则，同时核对日常配置哈希不变。这不是用户日常应用、真实休眠或 Mac 上 Clash Party 的实机验收。
