# 临时分流与到期恢复

应用详情中的“设置期限”可为一个有精确程序路径的应用选择 15、30 或 60 分钟的直接联网/跟随已绑定代理组。页面确认展示到期恢复的联网方式和代理组；不修改全局默认规则。

## 恢复规则

- 首次设置保存该应用当前的联网选择。续期仍恢复第一次临时设置之前的选择，不逐层叠加临时状态。
- 普通手动改选或选择性导入该应用的联网方式，会取消它原有期限；只导入资料不会取消期限。旧定时任务不能覆盖新选择，辅助进程补充保留同一期限。
- 到期和“现在恢复原选择”都通过普通配置校验、网络检查、独立事务守护、内核重载和确认流程，不回放旧订阅或整份配置。应用自身的旧连接不会强制断开。
- 有临时任务时，更换统一代理策略会被拒绝；先结束临时分流，以免恢复到已被替换的组。仅在 Clash Party 中切换现有组的节点仍可正常跟随。
- 失败不等于已恢复：内核离线、程序身份失效、外部配置冲突或网络检查失败时，保留期限和当前设置，页面显示“到期待恢复”；后台退避重试，可查看详情或手动恢复。

## 后台边界

期限、原选择和随机任务编号保存在分流事务与本机管理记录内。每个用户数据目录最多一个独立 Node 期限守护，处理多个应用；就绪握手必须读到本次事务，不能使用旧 PID 文件宣称成功。普通事务守护仍负责未确认写入的超时回退。

关闭窗口或退出 AppRoute 界面后，已经启动的期限守护继续运行。电脑重启会结束进程，须重新打开 AppRoute，后台再核对持久化期限；不会偷偷启用开机启动。睡眠期间不能执行恢复，唤醒后按已保存的绝对时间核对。若独立守护本身被结束而界面也已退出，需重新打开 AppRoute 才能续接。

## 实现与验收

- 业务入口：`TemporaryRoutingService`；可信内部事务上下文携带期限，页面不能指定旧选择或伪造期限记录。
- 独立守护：`temporaryGuardian.ts`；专属锁、有限就绪等待、持久化状态读取、失败退避。后台启动/定时检查负责续接。
- 单元回归：到期、续期、手动改选、策略保护、helper 补充、过期请求、守护失败、恢复失败及重建服务。
- 反向验证：故意让普通改选保留旧期限时，测试必须失败。
- 真实内核隔离验收：复制出的测试程序建立连接，独立期限进程到期恢复，再核对新连接从 `ProcessPath` 回到原有 `Match`，同时比较日常配置哈希。
- 四语桌面验收使用隔离演示数据，覆盖取消/Esc、应用、到期待恢复和提前恢复；它不替代 Mac 实机或真实睡眠验收。

导出设置与跨机导入不延续旧电脑的临时期限；旧备份恢复必须经过当前差异预览。操作记录标明临时设置和结束操作；涉及临时状态的记录不提供普通单步撤销。
