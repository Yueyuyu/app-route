# 测试隔离与反向验证

## 关键测试确实抓得住问题

运行 `npm run check:regression-proof`。登记在 `scripts/lib/regressionProof.mjs` 的三个场景分别保护原有规则、导入预览有效期和备份删除指纹。执行器复制源码与目标测试到 `.runtime`，逐个执行正常通过 → 受控破坏导致目标断言失败 → 恢复后通过，最终检查原工作树未变化并清理本次副本。

破坏点缺失或多处命中、编译/加载错误、超时、测试跳过、破坏后仍通过都直接失败。报告在 `output/regression-proof/`，包含源码哈希、提交和暂存树。受控破坏证明测试能捕获指定保护缺失，不宣称复现了所有历史缺陷。新增关键修复应登记实际故障或相应破坏点；普通文案不要求反向验证。

本地程序提交门禁与 Windows/macOS CI 都运行这项检查。发布仍执行完整原有检查。

## 共用桌面夹具

`scripts/lib/testSandbox.mjs` 为多语言、设置与首屏检查提供统一创建、启动和退出接口：

- 每次创建独立用户目录；环境变量采用最小允许列表，不继承代理地址、令牌及 Node 注入参数。
- 使用演示后台与虚构应用。`fixtureBoundary.mjs` 拦截后台对夹具目录外文件、网络及额外子进程的访问；发生越界即使被调用方捕获，也会在退出检查中失败。界面外部 HTTP/WebSocket 请求被拒绝并记录。
- 使用业务定位器、IPC 结果及 `waitForState` 的截止时间等待。固定睡眠只可用于明确测试延迟，不能代替就绪断言。
- 正常关闭检查本次桌面与后台退出；关闭卡死时只结束持有的子进程对象并报告失败，禁止按进程名批量终止或关闭用户正在使用的软件。

这些是可信测试代码的防误操作边界，不是操作系统安全沙箱，不能执行不可信代码。真实代理、订阅刷新、断网和休眠验收另走实机流程，不能用演示数据写成真实联网通过。

新增测试优先复用共用入口。必要的夹具文件保留在被忽略的 `.runtime`，自动截图使用虚构数据；发布或提交日志前仍应核对敏感信息。
