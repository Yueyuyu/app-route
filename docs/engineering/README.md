# 开发与验收入口

先按任务查 [模块索引](subsystems.md)，再查 [经验库](lessons.md)。提交门禁仍以 [PREFLIGHT](../../.github/PREFLIGHT.md) 为准，测试与发布分层仍以 [CI](../CI.md) 为准。

## 一次修改的交付

1. 写清触发条件、修改前后行为与不变的边界；识别实际执行入口，搜索同类调用方。
2. 修改实现及相关契约。内部重构没有改变契约时，不机械补写文档。
3. 对关键故障修复证明回归有效：同一测试在旧行为或受控破坏下因目标断言失败，正常实现通过。编译失败、超时、跳过不算抓住问题。只在临时副本中恢复旧代码或注入破坏。
4. 使用隔离配置与虚构应用，等待业务状态，清理自己启动的进程；真实网络验收单独记录，不混入自动 UI 测试。
5. 界面变更附带可复查的截图与操作结果，写明尺寸、语言、源码版本及未覆盖场景。预览不能替代功能断言。
6. 依次执行精确暂存、验证、提交、推送与该 SHA 的 CI。提交正文保留变更、验证、未验证三项；本地 hook 自动附上验证对应的 Git 树和门禁命令。机器只检查记录格式与版本一致性，不替作者证明描述真实。

## 经验如何维护

只收录已发生且有证据的错误。每条最多写现象、原因、拦截办法和测试入口，不保存私密日志。相同原因在三个独立任务出现时，优先升级为共用实现、测试或门禁，再缩短文字；已失效规则删除或标记被替代。更新业务经验库不等于修改 Codex 全局记忆。

## 验收记录模板

提交标题仍为 `<type>: <中文描述>`，正文示例：

```text
变更：导入预览过期时停止应用，未选应用保持原设置。
验证：npm run check；预览指纹保护被移除时，对应回归断言失败。
未验证：Mac 真机分流；本轮仅使用隔离桌面与模拟内核。
```

不要填写“已测试”后省略命令或范围，也不把未运行项写成通过。文档改动写明链接检查；没有适用的反向测试时注明原因。CI 的跨平台结果另以实际运行链接记录，提交前不能预报成功。
