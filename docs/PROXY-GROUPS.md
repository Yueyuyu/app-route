# 代理组跟随

- 默认组保存在 AppRoute 本机状态，应用规则的目标是组名，不是组内当前节点名。组内换节点不重载配置，不关闭已有连接，AppRoute 退出后规则仍由 Mihomo 执行。
- 首次绑定或更换组会统一迁移全部已有代理应用，通过校验、备份、守护、网络检查和确认事务；直连应用记录不改变。失败恢复上一个目标及默认组。
- 多组选择彼此独立，用户选择自己常用的配置命名组；多个候选时不擅自猜测。首版支持 Selector、URLTest、Fallback；GLOBAL 内置组不作为可绑定配置组。
- 页面每 5 秒读取当前组的逐层选择。负载均衡子组显示按连接分配；循环、未知类型、缺失成员不返回猜测的节点。
- “组当前选择”只是内核现在选择的目标。“实际连接节点”来自已观测连接的 chains，核对精确进程、命中规则和应用时间。旧连接使用旧节点是正常情况，不主动断开。
- 跟随组允许含 DIRECT / REJECT，当前选择到它们时必须显示直连或拒绝，不能标为远端代理已验证。最近五分钟内的测速记录仅代表该次探测，不是持续在线承诺。
- 手动组不会自动故障转移。沿用现有组时，自动选择／Fallback 由用户既有 Clash Party 策略负责，AppRoute 不改这些策略。也可在“代理策略”创建 AppRoute 独立自动组，详见 [代理策略](PROXY-STRATEGIES.md)。整个已有组从订阅中消失时，客户端重新生成覆写会跳过失效目标，相关流量沿用原规则；页面提示重新绑定，不静默切到别的组。
- 用户旧版本保存的固定节点不会在程序启动时自动迁移；只有明确绑定操作才统一更新。原有配置、系统代理、TUN 和恢复入口保留。

验证覆盖及尚未完成的真实重启／订阅切换验收见 [VERIFICATION.md](VERIFICATION.md)。
