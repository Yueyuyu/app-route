# 项目基础说明

## 名称与定位

- 名称：AppRoute 应用分流。
- 仓库：`Yueyuyu/app-route`，公开源码，MIT 自有代码许可。
- 首版平台：Windows。
- 使用者：希望按软件选择联网方式，而不直接编辑复杂代理配置的人。
- 首个正式集成目标：现有 Clash Party。架构目标是兼容多种执行端，而不是绑定某一个客户端名称。

## 核心使用流程

扫描或手动添加应用 → 选择联网方式 → 查看待应用变更 → 应用 → 查看实际连接结果 → 必要时恢复。

初始示例数据必须明确标注；扫描不承诺识别所有软件、商店应用、便携版和子进程。

## 统一术语

| 概念 | 定义 |
| --- | --- |
| 应用 | 用户理解的软件，可关联多个进程；显示名称不作为稳定唯一标识 |
| 进程匹配 | 按进程名或完整可执行文件路径匹配；扫描得到路径不等于已经启用路径规则 |
| 按现有规则（rule） | 沿用所选执行端的现有规则；当前 Clash Party 预览显示“按 Clash 规则” |
| 直接联网（direct） | 不通过远端代理节点，仍可能由本机内核接管后直接连接 |
| 强制走代理（proxy） | 对已识别、已接管的连接使用明确的代理出口；接管与出口都满足条件时才可应用 |
| 内核 | 执行连接和路由规则的引擎，例如 Mihomo；不一定有图形界面 |
| 客户端 / 配置所有者 | 保存订阅、生成内核配置、管理重启的程序，或用户指定的独立配置 |
| 代理端口 | HTTP / SOCKS5 等流量入口；与管理 API 地址分开配置 |
| 流量接管 | 使应用连接进入分流执行端的机制；端口连通性检测不能替代它 |

## 当前阶段

`0.2.0-preview.1` 已从原型进入本机集成测试：

- 已实现：搜索/分类/筛选、批量草稿设置、编辑及移除、真实只读扫描、草稿保存/导出、说明页。
- 已建立：客户端无关的数据类型、执行端接入契约、文档、测试及 CI。
- 已实现：命名管道连接、规则应用、独立全局覆写、真实连接检查、事务备份、120 秒独立守护及离线恢复。
- 待验收：真实客户端重启、订阅切换、休眠与异常退出矩阵。
- 未实现：Electron 封装和安装包、其他代理客户端。

草稿存于浏览器 localStorage；运行状态、备份和恢复工具存于 %LOCALAPPDATA%\AppRoute。用户数据不放入源码目录。

## 首个可用分流版本的验收标准

1. 明确显示连接的客户端、内核、模式、能力及缺少的条件；未就绪时不允许假应用。
2. 对一个真实测试应用，分别验证按规则、直连、代理三种选择及其实际新连接。
3. 修改设置有待应用状态，成功后区分配置状态和观测状态；失败说明可操作原因。
4. 选择代理组时校验存在性、最终出口及协议能力；组指向 DIRECT 或缺少接管能力时不得冒充强制代理。
5. 保留既有用户规则，能够恢复；验证客户端重启、订阅更新、切换配置后的行为。
6. 原有长连接不会假装已经切换；提示重新连接，并在用户选择时仅处理相关连接。
7. 无需编辑源代码或手写规则，即可完成上述核心操作。

## 首版操作原则

未设置应用保留原有分流；列表复选框只表示批量选中，三段选择器表示联网方式。配置写入前显示变更；“临时停用 AppRoute 规则”不等于关闭整个代理软件。

不把“只代理勾选的应用、其他全部直连”当作默认行为；它需要单独的全局策略设计和流量覆盖验证。
